git diff - показывает различия между состояниями файлов, можно сравнивать рабочую папку, индексы, коммиты

git show - показывает содержимое конкретного коммита конкретно дату, автора, сообщение и изменения

git log - показывает историю коммитовв 



команда git log -S"def" --oneline -- lab03/calc.py ищет коммиты, в которых изменилось количество вхождений строки def в файле


оманда git blame lab03/calc.py показывает, каким коммитом и автором была добавлена или изменена каждая строка файла
вывод:
в ходе работы я создал несколько версий калькулятора, сохранил их отдельными коммитами и научился сравнивать изменения, просматривать историю и определять происхождение строк кода



команда git restore lab03/calc.py восстанавливает файл до состояния, соответствующего текущему индексу git если индекс чистый, файл возвращается к последнему коммиту, а незакоммиченные изменения в нём теряются



команда git restore --source=HEAD~2 lab03/calc.py восстанавливает содержимое файла из указанного более раннего коммита. она меняет рабочую копию, но сама по себе не создаёт коммит.


после этого git diff позволяет увидеть отличия старой версии от последней закоммиченной версии. Повторный git restore lab03/calc.py возвращает актуальное состояние файла.






Команда git revert HEAD  создаёт новый коммит, который отменяет изменения выбранного коммита. Исходный коммит остаётся в истории.

Команда git reset --hard перемещает текущую ветку на выбранный коммит и сбрасывает индекс и рабочую директорию. При этом незакоммиченные изменения теряются, а коммиты могут исчезнуть из обычной истории ветки.

В опубликованной истории безопаснее использовать git revert, потому что он не переписывает существующую историю и позволяет другим участникам сохранить согласованную последовательность коммитов.



Тег — это имя, которое указывает на определённый коммит и позволяет обозначить конкретную версию проекта, например v1.0.

Ветка — это подвижный указатель на коммит, который перемещается при создании новых коммитов в этой ветке.

Тег удобно использовать для обозначения релизов, а ветки — для параллельной разработки и экспериментов.
